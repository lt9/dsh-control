# dsh-control Constitution

**Version**: 1.0.0 | **Ratified**: 2026-10-29 | **Last Amended**: 2026-10-29

本文件全部条款提炼自 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)（下称契约），
逐条注明出处，不发明新规矩。契约是后端实现依据与前端唯一对接依据，
**改契约必须先改契约文件本身**（契约前言）。本文件与契约冲突时以契约为准，
并同步修订本文件。

## I. 硬性边界（出处：契约 §0）

1. **只操作自己创建的东西**。frp 现有隧道、nginxWebUI 现有站点、阿里云现有解析
   记录一律只读；创建/删除只允许作用于本控制台登记过的对象（按 `dns_record_id`、
   `frp_proxy_id`、`ng_*` 主键精确删）。（§0.1）
2. **不可逆动作全部收在 release 流程里并要求二次确认**。frp 隧道、nginxWebUI 配置、
   阿里云解析删除属于不可逆动作；服务端校验 `confirm == slug`，该值由前端填，
   用户用长按确认而不是打字。（§0.2，交互细则见 §9）
3. **释放不删容器**：只 `docker stop`；数据目录、容器、镜像一律保留；列表仍可见，
   状态 `released`，不提供恢复入口。（§0.3）
4. **密钥纪律**：任何密钥、token、AK/SK 不写日志、不进错误信息、不进 URL query；
   列表和详情默认打码，完整值只在明确的 reveal 动作里返回。（§0.4）
5. **主机侧执行一律走 SSH + `docker` 命令**，不在被管主机上常驻 agent。（§0.5）

## II. 数据库三条规矩（出处：契约 §2.0，不可违反，评审会逐条查）

1. **不用外键**。表之间只有逻辑关联（`host_id`、`instance_id` 这类列 + 普通索引），
   没有 `FOREIGN KEY` 约束，级联行为一律在程序里显式写；删除父行不自动动子行，
   谁删谁负责，删完记 `events`。（§2.0.1）
2. **不写联表查询**。仓储层一张表一张表查，用 `WHERE id IN (...)` 批量取回后在
   Python 里组装；一个请求里不许出现 `JOIN`；列表接口组装详情同理。（§2.0.2）
3. **每个字段都要有备注**。SQLAlchemy 每个列写 `comment="…"`，Alembic 迁移的
   `op.create_table` 列同样带 `comment=`，落库后 `psql` 里 `\d+ 表名` 必须能看到
   中文说明；表本身也要 `Comment`。没有备注的列不许合入。（§2.0.3）

配套命名与类型约定（§2.0 顺带段）：布尔列用 `is_`/`has_` 前缀或 `enabled` 这类
形容词；时间列统一 `created_at`、`updated_at`、`*_at`，一律 `timestamptz` 存 UTC，
显示层转 `Asia/Shanghai`；不用软删；金额/字节用 `bigint`；状态列用 `text` +
CHECK 约束，不用 PG enum。

本控制台的库属于最高敏感级（集中存各实例登录密钥）：可与别的项目共用 PG 实例，
但不要共用库。（契约 §2 首段）

## III. 密钥与凭证纪律（出处：契约 §0.4、§2、§4、§6.1.6）

1. 密钥、token、AK/SK 不写日志、不进错误信息、不进 URL query。（§0.4）
2. 列表和详情默认打码，完整值只在明确的 reveal 动作里返回；详情响应里 `access`
   只有 `has_token`/`token_masked`/`captured_at`，没有任何完整值——把完整值放进
   详情等于多一处泄露面。（§0.4、§4 `access` 段）
3. 列表接口连 mask 都不给；reveal 是一次有意的动作，且要求 `X-Requested-With`
   头。（§4 `access` 段）
4. `mirror_token`（分发渠道令牌）**只写不回显**：API 任何出口只给
   `token_set: true/false`——与运维密钥的「明文可读回」刻意不同。（§2 末、§6.1.6）
5. token 落库与事件一律去重：抓到的 token 与库里最新一条比对，值没变就什么都不写；
   值变了才落库并记 `token_captured` 事件。（§3 末段）

## IV. 交互纪律（升格为铁律，出处：契约 §9「交互做减法」）

契约原文即「落到界面上是硬要求」，此处升格为评审必查项：

1. **全系统只有两处需要用户输入**：登录页粘贴密钥、给实例改备注名（就地编辑）。
   新建、释放、重启、探活都不许要求打字。（§9）
2. **新建只有一个动作**：点「新建」→ 自动填好的确认卡（全部程序生成）→
   点「开始部署」；换主机是卡片上一次点击，不是表单。（§9）
3. **危险与不可逆动作用按住确认**（长按 1.5 秒，松手取消）配合一屏后果清单，
   不用弹窗套弹窗；服务端仍要求 `confirm == slug`，由前端填。（§9、§0.2）
4. **升级/重建 = 一次点击 + 一张后果卡**（重建容器、会话短暂打断、数据不动、
   登录链接不变、目标镜像是谁），零打字。（§9）
5. **密钥不进列表接口**；详情页进页面 reveal 一次，平时只显示打码与时间；
   界面不轮询抓密钥；没变化不产生任何事件。（§9，去重规矩在 §3）
6. **不显示用户用不上的字段**（镜像 id、内部状态机原始值收进次要位置或不显示）。（§9）
7. 命名与域名全部程序生成：标签 `dsh-NN` 服务端生成、创建后不可改，派生名一律
   从 slug 出；`owner_label` 是事后可改的备注，不在新建流程里问。（§6.1.1）
8. **界面做减法，解释进 tips**：解释性文字一律走 tips（设置页 `HelpTip` 先例），
   页面正文只留可操作内容；机制参数（cookie 时长、限流阈值等）不做说明书上墙，
   只在错误发生的当下于错误文案里说。新页面评审必查此项。（§9）

## Governance

- 本 constitution 是契约摘录，不是平行权威：任何规矩以
  [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) 原文为准；改契约先改契约，
  再同步本文件（契约前言）。
- 评审按本文件逐条核查，数据库三条规矩「评审会逐条查」（§2.0 标题括注）。
- 版本号遵循语义化版本：MAJOR=删除/重定义原则，MINOR=新增原则或实质扩充条款，
  PATCH=措辞澄清与错别字修正。每次修订更新 Version 与 Last Amended 日期。
